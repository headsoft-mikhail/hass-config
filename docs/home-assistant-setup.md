## Сервер и доступ

- URL: http://homeassistant.local:8123, локальная сеть Mac.
- HAOS на Raspberry Pi 5 в Argon ONE V3; внутренний NVMe; оригинальный БП 27 Вт; BLSTR DAC отсутствует.
- После переезда с RPi4 выполнено предложенное системой обновление прошивки RPi. Скрипты/аддоны Argon не устанавливались; управление вентилятором и I2C ещё не обследованы. Прошивку RP2040 корпуса не путать с прошивкой RPi.
- Роутер и HA питаются от EcoFlow RIVER 3. Два ZBT-1 подключены к HA раздельно для Zigbee и Matter/Thread. Aqara E1 подключён к USB HA только ради питания.
- Во встроенном браузере владелец самостоятельно вошёл под отдельным пользователем. Доступ к настройкам, интеграциям, устройствам, приложениям и Studio Code Server подтверждён. Разрешено чтение; наличие прав записи не означает разрешение изменять систему.
- API владелец пока не хочет настраивать. Advanced SSH & Web Terminal установлен; старый SSH-доступ не проверялся, пароль из настроек не извлекался.

## Конфигурация и Git

Серверный репозиторий расположен прямо в /config. Обычный процесс в обе стороны: commit в master → push → pull на другой стороне. Серверный pull владелец выполняет в Studio Code Server. Автоматического развёртывания нет.

Studio Code Server открывает /config. Чтение/копирование файлов проверено; записи и терминальных команд не выполнялось. Редактор оставлен в Restricted Mode, запрос Trust Folder & Continue отменён. Способ локальной/серверной правки выбирается в плане каждой задачи; перед переносом сравнивать актуальный серверный файл с Git.

Порядок согласований и правила безопасности находятся в [AGENTS.md](../AGENTS.md). Перезапуск, reload, изменение настроек и управление сущностями отдельно согласуются. Перед применением нужна проверка конфигурации целевым HA; локальный YAML parser её не заменяет.

## Инвентаризация

Через Studio Code Server только чтением получены core.entity_registry, core.device_registry и core.area_registry. Шаблоном HA дополнены имена загруженных entity. Исходные реестры целиком в Git не копировались; состояния, credentials, options, MAC и серийные номера в каталог не включались.

- 180 записей устройств, включая программные и служебные.
- 1350 зарегистрированных entity: 353 отключены, 12 скрыты; эти признаки могут пересекаться.
- 1007 загруженных entity, в том числе 10 без регистрации.
- Объединённый каталог: 1360 точных ID в [home-assistant-entities.md](home-assistant-entities.md).

states/device_entities в шаблоне не включают отключённые entity, поэтому не подходят для полной инвентаризации. Текущий снимок не гарантирует неизменность: перед записью сверять затронутые ID, параметры и зависимости с HA. Физический смысл устройств и автономные правила вне HA — [system-notes](home-assistant-system-notes.md).

JSON-снимок нужен только локально для повторной обработки и хранится в игнорируемой tmp/. В репозитории один постоянный полный каталог — Markdown, без дублирующего JSON. Текущие задачи также находятся только в tmp/ и не являются постоянной документацией дома.

## Применение подготовленной интернет-конфигурации

Локально подготовлен binary_sensor.internet_available со встроенными delay_on/off по 17 секунд, опросом исходного Ping раз в 15 секунд и простыми уведомлениями по его подтверждённым on/off переходам. В работающем HA это ещё не применено. Перед развёртыванием отдельно согласовать и выполнить для записи 8.8.8.8 count=1 и отключение штатного polling; проверить отсутствие конфликта нового entity_id, актуальность серверных файлов и конфигурацию самим HA. Ожидаемый diff не содержит изменений actions уведомлений. Для отката вернуть прежние YAML и настройки Ping.
